recommendSkills() ada tetapi pencarian penggunaan tidak menemukan pemanggil. Backend menyediakan manifest dan pembacaan instruksi. sendWithSkill() justru menyisipkan konteks RAG/task lalu mengirim prompt.

Graphify: sudah aktif

before_agent_start menjalankan graphify query dan menyisipkan hasil. Output berupa teks dengan budget 1.200 per graph, batas prompt 2.000 karakter, dan batas konteks gabungan 12.000 karakter. Perlu kandidat terstruktur sebelum ranking.

Review: pemeriksaan whitespace

Preset KAI/MBI memberi nama “Review” pada git diff --check. Jev bisa menambah triage semantik; hasilnya belum merupakan bukti bahwa kode benar atau test mencakup aturan.

Pilot yang disarankan: saran skill

  1. Baseline: ukur pilihan Pi saat ini, lalu pembanding keyword yang sudah tersedia. Fungsi keyword belum aktif, jadi jangan menyebutnya perilaku produksi.
  2. Dataset: kumpulkan sekitar 50–100 prompt Indonesia/Inggris yang diberi label manusia. Sertakan none, skill mirip, dua kebutuhan, instruksi eksplisit, dan skill manual-only. Ini rancangan evaluasi, belum dataset yang tersedia.
  3. Integrasi: layanan Jev terpisah dari model chat. Baca manifest, batasi input, validasi ID hasil, lalu tambahkan saran singkat ke konteks. Hindari mengirim seluruh isi skill/kode jika metadata cukup.
  4. Kegagalan: opsi nonaktif, timeout berbatas, pembatalan, 429/error/malformed response → alur Pi normal tetap berjalan. Cache memakai prompt + katalog/fingerprint + model + versi pertanyaan; jangan mengabaikan konteks yang memengaruhi keputusan.
  5. Evaluasi: gunakan data terpisah untuk menyetel threshold dan menguji hasil. Ukur ketepatan, unnecessary suggestion, latency p50/p95, fallback rate, biaya, dan hasil task. Multi-skill boleh tetap dipilih Pi.
  6. Keputusan lanjut: aktifkan jika saran lebih tepat dari baseline dengan latensi yang diterima. Jika tambahan request hanya memperlambat tanpa memperbaiki hasil, jangan perluas.

Apa yang didukung riset, apa yang belum

Bukti resmi untuk skill suggestion

Cookbook TypeSafe menguji dua tahap seleksi pada katalog Hermes: ranking lalu verifikasi kandidat. Pada evaluasi mereka, salah memilih skill turun dari 16,8% ke 7,3%. Dataset dibuat dari skill dan memakai Jev 1.12 serta Haiku; hasil ini tidak membuktikan angka yang sama di Pi/Kern Studio.

Cookbook skill suggestion
Bukti reranking dan batas retrieval

Cookbook resmi menunjukkan perbaikan urutan kandidat pada dataset hukum. Itu membuktikan pola retrieve → rerank layak diuji, bukan jaminan kualitas code search. Reranking hanya melihat kandidat yang berhasil ditemukan.

Cookbook reranking
Confidence bukan jaminan kebenaran

Choice/Score punya confidence; Noul memberi probabilitas ya tanpa field confidence terpisah. Threshold bergantung pada domain dan bentuk pertanyaan. Studi independen melaporkan threshold biner perlu tuning pada sebagian dataset.

TypeSafe confidence · Evaluasi independen, 29 September 2026
Kontrak Pi sudah diverifikasi

Runtime lokal melaporkan Pi 1.0.0. Types terpasang mendefinisikan before_agent_start, tool_call dengan block/reason, dan session_before_compact. Dokumentasi mengingatkan bahwa ringkasan custom mengelola pelacakan file sendiri.

Pi extensions · Pi compaction
API, biaya, dan batas model

OpenRouter menyediakan Decisions API untuk typesafe/jev-1.13; jangan memasukkannya ke alur chat completions biasa. Harga terdaftar US$0,042 per juta input token dan output gratis. Ilustrasi 5.000 billed input token × 1.000 request = US$0,21; itu bukan pengukuran workload Kern Studio. Latensi harus diukur dari jaringan pengguna.

API OpenRouter · Model dan harga
Alasan menunda enforcement dan compaction

TypeSafe mendokumentasikan penurunan kualitas pada konteks penuh detail tidak relevan, reasoning berlapis, dan konten adversarial. Semua ini muncul pada pemeriksaan aturan dan histori panjang. Kurangi konteks dan pertahankan aturan deterministik di kode.
